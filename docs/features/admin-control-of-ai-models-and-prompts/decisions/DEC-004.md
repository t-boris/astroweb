## Context

deepInterpretationCache, forecastCache, premiumPdfCache and newsCache are keyed by inputs only, without model or prompt. After a change the admin would keep seeing old cached answers (deepen and premium PDF are cached indefinitely), so a change would look like it did nothing.

## Alternatives

1. Keep serving cached output until it expires (no extra tokens, but changes to deepen and PDF never show for cached profiles)
2. Delete the cache collections on save (same effect, but destructive and slow)

## Decision

Each task's settings carry a version that changes on every save; the cache key of a cached task includes the version of its settings. New requests after a change generate fresh output; old cache entries are simply no longer hit. Content already saved for users (Oracle history, compatibility readings, letters, generated PDFs they downloaded) is not touched.

## Reason

A change is visible on the next request, and stale output can never be served under new settings.

## Consequences

The first request per profile after a change spends tokens again (premium PDF is the most expensive: four sections). With no override the version is the default one, so today's cache entries stay valid on release.
