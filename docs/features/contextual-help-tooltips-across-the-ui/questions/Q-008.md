## Question

The plan and REQ-003 exclude "astrologer workspace screens (including AstrologerNotes)" from help bubbles, but AstrologerNotes ("What your astrologer knows", /profile/:id/notes) is an end-user page. Should it get help bubbles?

## Why it matters

Checked: DEC-003 (end-user screens in, "admin and astrologer workspace" out; reason: internal users need no onboarding help), REQ-003 (AC "No help bubbles are added to admin or astrologer workspace screens"), plan I-6 ("a check that admin and astrologer workspace screens (including AstrologerNotes) get no help bubbles"), Q-003 answer B. In the code AstrologerNotes is the signed-in customer's own dossier: it is linked from the Astrologer panel ("What the astrologer knows"), and the customer edits interests, confirms or deletes notes and can "Forget everything". It uses native title tooltips on icon-only buttons (Confirm, Delete). The only internal screen in the code is Admin.tsx; no separate astrologer workspace exists.

## Options

- **A**: Treat AstrologerNotes as an end-user screen and cover it (icon-only buttons, 'needs your OK', interests, 'Forget everything'). The 'no help' check applies to Admin only. DEC-003's wording is clarified: the 'astrologer workspace' does not exist in the code.
- **B**: Keep it excluded as the plan says. It stays without help bubbles, and the 'no help' check covers Admin and AstrologerNotes.

## Recommended

A

## Answer

A. Treat AstrologerNotes as an end-user screen and cover it. The 'no help' check applies to Admin only.
