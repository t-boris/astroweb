## Statement

A short public privacy page at /privacy (English) and /ru/privacy (Russian), following the bilingual URL pattern of DEC-003, states what analytics data is collected through GA4/Firebase Analytics. It lists the cookies used, explains how consent works and how to change or withdraw it, and says that purchase and subscription events (start, renewal, cancel) are always sent to GA4 server-side (DEC-001, DEC-005, DEC-007). With consent, these events carry the real GA client_id and, when the user is signed in, the Firebase Auth uid as user_id. Without consent, they carry no user_id and no other user identifier. Instead, each event carries a pseudonymous client_id: a deterministic one-way hash of a Stripe identifier for that event (the checkout session id for purchases). The page says plainly that this identifier is pseudonymous rather than anonymous, because it can be linked to the payment record held in Stripe/Firestore. For the astrologer subscription, the page states that the analytics consent state is recorded when the subscription checkout starts and stored with the subscription. That recorded state applies to all later renewal and cancel events of the subscription, and withdrawing consent later on the site does not change it (DEC-007). The page explains that a subscriber who wants attribution of these subscription events to stop must contact the operator at astroweb@mobilemindai.com. The page never mentions birth data. It names MobileMind AI as the site operator and astroweb@mobilemindai.com as the contact for data and privacy questions. Both the consent banner and a site footer link to the page. The pages are public routes in App.tsx and are included in sitemap.xml and the hreflang set. The policy text must match what analytics actually collects.

## Acceptance Criteria

- [x] GET /privacy renders the English page and GET /ru/privacy renders the Russian page without sign-in.
- [x] Both pages name 'MobileMind AI' as the operator and show astroweb@mobilemindai.com as a mailto: link.
- [x] Both pages describe GA4/Firebase Analytics, the cookies it sets, Basic Consent Mode behaviour and the server-side purchase and subscription start, renewal and cancel events.
- [x] Both pages state that server-side purchase and subscription events are sent to GA4 whether or not consent was given.
- [x] Both pages state that with consent, server-side events carry the GA client_id and, for signed-in users, the Firebase Auth uid as user_id.
- [x] Both pages state that without consent, server-side events carry no user_id and no other user identifier, only a pseudonymous client_id that is a deterministic one-way hash of a Stripe identifier for that event (the checkout session id for purchases).
- [x] Both pages state that this pseudonymous identifier can be linked to the payment record held in Stripe/Firestore, and none of the text calls these events fully anonymous.
- [x] Both pages state that for the astrologer subscription, the analytics consent state is recorded at subscription checkout and applies to all later renewal and cancel events of that subscription.
- [x] Both pages state that withdrawing consent on the site later does not change the consent state recorded for an existing subscription.
- [x] Both pages explain that a subscriber can ask the operator at astroweb@mobilemindai.com to stop attribution of their subscription events.
- [x] Neither page mentions birth data.
- [x] Both pages tell the user how to reopen the consent choice and withdraw consent, and give a working control or link to do so.
- [x] The consent banner links to the privacy page in the current UI language.
- [x] The site footer, shown on public pages, links to the privacy page in the current UI language.
- [x] Both pages carry their own title, description and canonical tag, plus reciprocal hreflang links, and appear in sitemap.xml.
- [x] Every event, parameter, identifier and cookie listed on the privacy pages matches what the analytics implementation (client, subscribeAstrologer checkout metadata and webhook) actually sends, stores or sets, and nothing collected is left out.
