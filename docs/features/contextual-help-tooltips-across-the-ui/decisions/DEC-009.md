## Context

Plan I-1 says "shadcn Popover/Tooltip primitives" and REQ-005 asks for one shared component. The existing web tests have no DOM environment.

## Alternatives

1. Radix Tooltip for pointers plus Popover for touch (two primitives, tap-vs-click close conflicts)
2. Radix HoverCard (ignores touch)
3. Add jsdom and @testing-library/react to test the component in Node (new dev dependencies)

## Decision

A single HelpBubble component is built on the Radix Popover primitive that radix-ui (already installed) provides, added as a shadcn component in web/src/components/ui/popover.tsx. Open state is controlled: hover opens after a delay, keyboard focus opens at once, a tap opens on touch, Escape and outside taps close. The open/close rules are pure functions in web/src/lib/helpBubble.ts. No runtime or dev dependency is added: tests are Vitest in Node (pure rules, server-rendered markup, EN/RU key checks), and the interactive behaviour is verified in a real browser.

## Reason

radix-ui is already the UI stack (DEC-001 needs a popover that fits a paragraph). Radix Tooltip and HoverCard ignore touch, so they cannot give the tap behaviour of DEC-002. The web tests run in Node without jsdom or Testing Library; adding them would be a library change that needs approval, and the pure rules plus a browser check cover the behaviour.

## Consequences

The hover timers and pointer-type handling are our code, kept small and covered by the pure rules. A media-query hook (lib/helpPointer.ts) decides whether an actionable element gets a "?" button: coarse-pointer devices get it beside the element (or as a corner badge in the page header), pointer devices render the element alone, so desktop markup and spacing are unchanged. If real DOM tests are wanted later, jsdom can be added with approval.
