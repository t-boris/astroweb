## Context

Settings must change without a deploy. Firestore is already the app's store, rules deny all client access, and the only runtime config today is featureFlags/personalAstrologer read per call.

## Alternatives

1. Firebase Remote Config server templates (built-in versioning, but a new API surface and dependency)
2. Environment variables / ANTHROPIC_MODEL (needs a deploy for every change)
3. Read Firestore on every request without a cache (simpler, one extra read per AI call)

## Decision

One document per AI task in `aiSettings/{taskId}` (model, request limits, prompt texts per language, version number, updatedAt, updatedBy). Functions read it through one loader with a 60-second in-memory cache per instance, so a saved change applies to new requests within about a minute. Access only through admin callables; firestore.rules stay deny-all.

## Reason

No new dependency or service, same pattern as the rest of the backend, cheap reads, predictable propagation time.

## Consequences

A change can take up to ~60 s to reach every running instance. The settings document becomes part of production state and must be validated on read.
