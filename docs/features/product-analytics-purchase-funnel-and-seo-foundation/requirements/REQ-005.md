## Statement

After analytics consent is granted, the web app sends a fixed set of GA4 funnel events at defined triggers with documented parameters; GA4 user_id is the Firebase Auth uid only for signed-in users, and no event or parameter contains names, birth data, places or emails.

## Acceptance Criteria

- [ ] profile_create_start fires once when /profile/new (create mode) is opened, with no parameters.
- [ ] profile_created fires once after createProfile succeeds, with no parameters (no name, date, place or time).
- [ ] chart_viewed fires once each time a profile page tab becomes active (including the initial tab), with parameter tab in {chart, planets, aspects, houses, interpretation, oracle, transits, compatibility, astrologer, premium}.
- [ ] paywall_viewed fires once per profile view and feature when a star-gated state is shown, with parameter feature in {interpretations, compatibility, oracle, premium_store}.
- [ ] begin_checkout fires once when the user starts a star-pack checkout, with parameters pack_id, value (USD price shown), currency = USD and items [{item_id = pack_id}].
- [ ] unlock_feature fires once after unlockFeature succeeds and charged stars, with parameters feature and stars (stars spent).
- [ ] astrologer_subscribe_start fires once when the user starts the subscription checkout, with parameters cadence and billing_period.
- [ ] ai_reading_requested fires once per request of a deepen, oracle, compatibility or letter generation, with parameter kind in {deepen, oracle, compatibility, letter}.
- [ ] letter_opened fires once per letter id per page load when a letter is shown, with no parameters.
- [ ] Every one of these events is sent only after analytics consent is granted; with consent declined or undecided none is sent.
- [ ] When a user is signed in, GA4 user_id equals the Firebase Auth uid; when signed out it is unset. No other user identifier is set.
- [ ] When the signed-in user is the admin account, events carry the default parameter traffic_type = internal so a GA4 internal-traffic data filter can exclude them; no email is sent.
- [ ] Page views use page_path templates: /profile/:id replaces profile ids for every /profile/<id>... route, and exactly one page_view is sent per route change.
- [ ] A grep of the analytics call sites finds no name, birthDate, birthPlace, email or coordinates in any event parameter (verified by a unit test of the event payload builders).
