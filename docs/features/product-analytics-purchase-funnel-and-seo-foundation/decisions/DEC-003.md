## Context

Language is currently detected on the client (localStorage/navigator) and there are no per-language URLs, so crawlers only see one language.

## Alternatives

1. English-only static meta
2. Russian-only static meta

## Decision

Serve the English landing page at / and the Russian landing page at /ru, each with its own title, description, OG/Twitter tags, canonical and reciprocal hreflang links, both listed in sitemap.xml.

## Reason

The app is already bilingual and a separate RU URL is the only way to be indexed in both languages without SSR/prerender.

## Consequences

A new /ru route is needed and the URL sets the UI language on the landing page. SEO effect remains limited by the client-only SPA.
