## Context

Besides the model, requests carry max_tokens, sometimes temperature, and on new models thinking/effort. Exposing every knob invites invalid combinations; exposing none prevents fixing truncated answers.

## Alternatives

1. Model only
2. Every API parameter including thinking, effort and top_p

## Decision

Per task the admin sets the model and the maximum output length; temperature is shown and editable only when the chosen model accepts it. Thinking and effort are set by the server from the model rules (DEC-002). Limits are validated on the server (output length within the model's limit; temperature 0..1).

## Reason

Covers the real needs (switch model, fix truncation, tune randomness on models that allow it) without letting a setting produce an invalid request.

## Consequences

Tuning thinking depth on the newest models needs a code change.
