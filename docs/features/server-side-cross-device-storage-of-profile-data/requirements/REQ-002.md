## Statement

Every compatibility reading generated for a profile must be persisted on the server, linked to that profile, and loaded from the server when the profile is opened on any device by its owner. Compatibility readings that exist only in a browser's localStorage (created before release) are uploaded to the server once, automatically, only for a signed-in owner — a caller authenticated with a Google account whose profile already has ownerUid matching that account, i.e. after claimProfiles has completed; the upload endpoint requires account authentication and rejects deviceId-authenticated calls. Local-only readings of anonymous (deviceId) users stay in the browser until they sign in; if such a user clears browser storage or switches browser before signing in, those readings are lost (accepted risk, mitigated by the DEC-003 sign-in banner).

## Acceptance Criteria

- [ ] A paid compatibility reading generated on device A is listed on device B for the same account without paying again.
- [ ] Clearing browser storage does not remove any compatibility reading that has been stored on the server.
- [ ] Readings created before release that exist only in localStorage become visible on other devices after the signed-in owner opens the profile once on the original device.
- [ ] The one-time upload of local-only compatibility readings starts only after claimProfiles has completed for the signed-in account on that device.
- [ ] The upload endpoint accepts a request only from a caller authenticated with an account whose uid equals the profile's ownerUid.
- [ ] The upload endpoint rejects a request authenticated only with a deviceId, and nothing is stored on the server.
- [ ] The upload endpoint rejects a request for a profile without ownerUid or with an ownerUid that belongs to another account, and nothing is stored on the server.
- [ ] For an anonymous (deviceId) user, local-only compatibility readings are not uploaded and stay in that browser's localStorage until the user signs in with Google.
- [ ] After the upload, the readings are loaded from the server, and opening the profile again on the original device does not upload them a second time or create duplicates.
