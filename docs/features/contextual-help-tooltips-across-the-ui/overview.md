# Contextual help tooltips across the UI

## Idea

Every meaningful UI element — especially astrological terms (planets, signs, houses, aspects, house systems), profile tabs, table columns and controls — gets a small help bubble (tooltip/popover) explaining what it is and why it matters, so a user can understand the interface without prior astrology knowledge.

## Problem

The app exposes many specialised terms (Placidus vs Whole Sign, orb, exactness, aspect types, houses, transits, Oracle, Astrologer) and tabs/controls without explanation. Today only the chart wheel has a data tooltip (position, house, aspects — no meaning), and a handful of icon buttons use native `title` attributes. Users without astrology background cannot tell what an element means or why they should care.

## Scope

IN: help bubbles for astrology definitions (planets, signs, houses, aspect types, house systems, orb/exactness), profile tabs, table column headers, chart controls (aspect filters, house-system toggle), and other primary UI controls on the profile screen and all end-user screens (profile creation, home, account, Premium/wallet, letters, compatibility); texts localised in EN and RU; a consistent visual component across the app. OUT (unless decided otherwise): admin screens and the astrologer workspace (first iteration), personalised chart-specific explanations generated by AI, a separate glossary page, guided onboarding tours, changes to the existing chart-planet tooltip data content.

## Existing behaviour

- Custom hover tooltip on chart planets: glyph, body, degree/sign, house, up to 5 aspects with orb. Shows data only, no explanation of meaning; hardcoded English strings ('House'). (`web/src/components/chart/ChartTooltip.tsx`)
- Profile detail tabs: chart, planets, aspects, houses, interpretation, oracle, transits, compatibility, astrologer (+ premium content). Tab labels come from i18n keys tabs.*; no descriptions. (`web/src/pages/ProfileDetail.tsx`)
- A few icon buttons use native HTML `title` attributes (archive, delete, expand/collapse, premium, account) — the only existing 'hover help'. (`web/src/pages/Home.tsx, web/src/components/Layout.tsx, web/src/pages/AstrologerNotes.tsx, web/src/components/chart/InterpretationView.tsx, RelationshipView.tsx`)
- Tables (planets, aspects incl. orb/exactness, houses) and aspect filter toggles that would carry term definitions. (`web/src/components/chart/PlanetsTable.tsx, AspectsTable.tsx, HouseAreasView.tsx, AspectFilters.tsx`)
- i18next with HTTP backend; supported languages EN (default) and RU; all UI strings live in translation.json. (`web/src/i18n.ts, web/public/locales/{en,ru}/translation.json, web/src/lib/language.ts`)
- UI stack is shadcn/ui on radix-ui (^1.4.3), which provides Tooltip/Popover/HoverCard primitives; no shadcn tooltip/popover component is installed yet under web/src/components/ui. (`web/package.json, web/components.json`)
- GA4 funnel taxonomy with strict per-event parameter allowlists (no PII); no help/tooltip event exists. (`web/src/lib/analyticsEvents.ts`)
- Responsive UI required (shadcn/ui + Tailwind); i18n EN+RU from start; planet hover tooltip was an MVP requirement. (`.planning/PROJECT.md`)
