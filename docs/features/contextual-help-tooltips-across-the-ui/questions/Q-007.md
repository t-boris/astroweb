## Question

The spec asks for a help bubble on the "house-system toggle" and on every house system "shown" in the UI, but the app has no house-system toggle and never displays the house system. What should the house-system help be?

## Why it matters

Checked: REQ-001 (AC "each ... house system shown in the profile tables, chart controls and filters"), REQ-003 (AC "Aspect filters and the house-system toggle have help bubbles"), overview Scope (chart controls: house-system toggle), plan I-3 ("the house-system toggle"). In the code, ProfileDetail.tsx always requests the chart with "koch" (line ~285); web/src/api/charts.ts accepts placidus | koch | whole-sign but no component lets the user choose and no component displays ChartResult.houses.system. The server can also fall back to whole-sign at extreme latitudes (functions/src/astro/chart.ts), so the system actually used can differ from the one requested. Adding a real selector would be a new feature (chart fetch, caching and interpretations are keyed to one system), not a help bubble.

## Options

- **A**: No toggle is added. Show the house system the chart actually uses as a small read-only label with a help bubble in the Houses tab (Koch by default, Whole Sign when the server falls back). Write help texts for all three systems (Placidus, Koch, Whole Sign). REQ-003's 'toggle' wording is amended to 'house-system label'.
- **B**: Add a real house-system selector (Placidus / Koch / Whole Sign) with help bubbles. This is a separate feature that changes what chart is fetched and cached, and needs its own requirements.
- **C**: Do nothing for house systems: no label and no bubble. The house-system parts of REQ-001 and REQ-003 are removed.

## Recommended

A

## Answer

A. No toggle is added. Show the house system the chart actually uses as a small read-only label with a help bubble in the Houses tab (Koch by default, Whole Sign when the server falls back). Write help texts for all three systems (Placidus, Koch, Whole Sign).
