## Context

Cross-device access requires an account. Anonymous users are identified by a localStorage deviceId, and today they can buy and spend stars from a device wallet.

## Alternatives

1. Keep anonymous mode for everything; cross-device only after voluntary sign-in
2. Require sign-in before creating the first profile

## Decision

Keep anonymous free usage (creating profiles, free features). Require Google sign-in before buying stars or performing any paid action (feature unlock, paid reading). Free anonymous profiles stay device-bound until the user signs in.

## Reason

Everything the user paid for is always tied to an account and survives a device change. The free, no-registration entry into the product stays intact.

## Consequences

Purchase and unlock endpoints must reject unauthenticated callers. The client must route anonymous users to sign-in (followed by claimProfiles) before a paid action. Free anonymous profiles can still be lost if the browser storage is cleared before sign-in.
