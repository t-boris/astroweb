# Полный план реализации «Личный Астролог» (Personal Astrologer)

Основываясь на обновленных спецификациях проекта, ниже представлен полный, пошаговый план архитектурных и функциональных изменений. План разделен на слои (База данных, Backend, Frontend) и фазы внедрения.

---

## 🗄 1. База Данных (Firestore) – Новые коллекции
Все эти коллекции будут закрыты от прямого чтения с клиента (доступ только через Backend-функции).
*   **`dossiers/{profileId}`** — Сводное досье на натальную карту: язык, форма обращения, город (для локализации транзитов и новостей), статус, интересы, а также `styleProfile` (изученный стиль общения астролога).
*   **`dossiers/{profileId}/facts/{factId}`** — Журнал фактов о пользователе (для прозрачности: откуда узнали, подтвержден ли).
*   **`oracleHistory/{profileId}/items`** — Перенос истории Оракула на сервер (чтобы AI мог учиться на старых вопросах).
*   **`letters/{profileId}/items`** — Хранение самих писем (сгенерированный HTML, тизер, вопросы с вариантами ответов).
*   **`letterJobs/{jobId}`** — Очередь задач для генерации писем с механизмом retry.
*   **`subscriptions/{profileId}`** — Данные о подписке (статус, частота, дата следующего письма).
*   **`consents/{profileId}`** — Согласия на обработку чувствительной информации.

## ⚙️ 2. Backend (Firebase Functions Node.js)
Основная логика, работа с AI (Claude Opus/Sonnet/Haiku) и интеграции.

**Новые фоновые процессы (Cron & Jobs):**
*   `scheduleLetters`: Cron-джоб (раз в 15 минут), проверяющий подписки и создающий задачу `letterJobs`, если пришло время отправить письмо в часовом поясе клиента.
*   `processLetterJob`: Воркер генерации. Собирает данные -> Делает запрос в Claude -> Формирует HTML -> Начисляет пользователю 1 ✦ (звезду) -> Отправляет Email (через **Resend**) и Web Push.
*   `dunningSweep`: Cron-джоб для обработки просроченных платежей в Stripe.

**Новые внутренние AI-Сервисы:**
*   `newsDigest.ts`: Поиск новостей (web_search через Sonnet/Haiku) по городу и интересам пользователя для привязки транзитов к реальности.
*   `transits.ts`: Расчет транзитов и их аспектов для текущего места жительства (релокация).
*   `factExtraction.ts`: Извлечение фактов из свободных вопросов пользователя (работает в фоне после вопросов Оракулу).

**Новые API Эндпоинты (Callables):**
*   *Управление досье:* `getDossier`, `updateDossierFact`, `forgetDossier`, `setInterestTags`, `exportUserData`.
*   *Управление письмами:* `listLetters`, `getLetter`, `answerLetterQuestion` (ответ тапом - бесплатно), `askInLetter` (свободный вопрос - стоит 1 ✦).
*   *Биллинг (Stripe):* `subscribeAstrologer` (создание checkout сессии), `pauseSubscription`, `cancelSubscription`.
*   *Push:* `registerPushSubscription` для PWA.

## 💻 3. Frontend (UI – React / Vite / Tailwind)
Пользовательский интерфейс и компоненты взаимодействия.

**1. Astrologer Hub (Хаб Астролога в профиле):**
*   Страница найма: Выбор частоты писем (раз в 2 дня, раз в неделю и т.д.), способа оплаты (месяц/год), выбор каналов доставки (Email, App, Push).
*   Возможность «назвать» своего астролога.
*   Интерфейс управления подпиской (пауза, отмена, смена частоты).

**2. Onboarding (Первичное анкетирование):**
*   Микро-форма на 2-4 шага перед наймом (Форма обращения/пол, город проживания, теги интересов, согласие на обработку данных).

**3. Letters Inbox (Почтовый ящик):**
*   Список пришедших писем.
*   Просмотр письма: безопасный рендеринг HTML (через DOMPurify).
*   Блок обратной связи под письмом: до 3-х кнопок с вопросами от астролога (тапы).
*   Поле ввода свободного текста: "Задать вопрос по теме письма".

**4. "Notes about you" (Управление досье):**
*   Раздел, где пользователь видит всё, что астролог о нем знает.
*   Списки фактов с указанием источника («Вы сказали нам», «Астролог понял из вашего вопроса»).
*   Кнопки редактирования/удаления каждого факта и глобальная кнопка "Forget everything" (Забыть всё).
*   Текстовое описание текущего стиля общения (например: *"Ваш астролог общается с вами в теплой, слегка шутливой манере"*).

**5. Системные UI:**
*   Регистрация Service Worker для PWA и запрос прав на Web Push уведомления.
*   Окно бесплатного "Тестового письма" (Acquisition hook) для пользователей без подписки.

## 🚀 4. Фазы внедрения (Дорожная карта)

Каждая фаза будет закрыта Feature Flag'ом, пока не будет готова вся логика биллинга и приватности.

*   **Фаза 1: Фундамент.** Настройка БД. Добавление "Notes about you" и формы интересов в UI. Существующий Оракул начинает учитывать досье при ответах.
*   **Фаза 2: Движок (Скрыто).** Разработка `scheduleLetters` и 2-этапного генератора писем на базе Claude Opus 4.8. Тестовая генерация на внутренних аккаунтах для замера реальной стоимости (COGS).
*   **Фаза 3: Доставка.** Разработка UI "Почтового ящика". Интеграция отправки тизеров на Email через **Resend** и PWA Push-уведомлений.
*   **Фаза 4: Биллинг.** Интеграция Stripe Subscriptions. Настройка webhook'ов. Разработка логики начисления звезд (✦) за каждое отправленное письмо.
*   **Фаза 5: Конфиденциальность.** Логика явного согласия для интимных вопросов (здоровье, отношения). Реализация удаления аккаунта каскадом (GDPR экспорт, "Забыть всё").
*   **Фаза 6: Рост и полировка.** Бесплатное "Пробное письмо" в UI (для вовлечения). Отладка промптов на идеальное качество текста. Дашборд аналитики.

## ✅ Статус реализации (deployed, gated за feature flag `featureFlags/personalAstrologer`)

Всё ниже задеплоено в прод (astroweb-dev), но закрыто фиче-флагом (allowUids = аккаунт Boris), поэтому не видно обычным пользователям до запуска.

**Фаза 1 — Фундамент ✅ (v2.6.0)**
- Коллекции `dossiers` (+`facts`), `oracleHistory`, `consents` (server-only — Firestore rules deny-all).
- `services/dossier.ts` (резолв сводки, факты с provenance/подтверждением, EMA styleProfile, forget/export), `services/factExtraction.ts` (Haiku, фоновое извлечение фактов), `services/astrologer.ts` (account-only + флаг).
- Оракул (`askOracle`) теперь инжектит досье + пишет серверную историю + извлекает факты.
- Callables: `getDossierData/updateDossier/setDossierInterests/setDossierConsent/addDossierFact/confirmDossierFact/deleteDossierFact/forgetDossierData/exportUserData`.
- UI: страница «Notes about you» (`/profile/:id/notes`), теги интересов, регистр, forget.

**Фаза 2 — Движок ✅ (v2.7.0)**
- `claudeRaw.ts` (tools+usage), `transits.ts` (релоцированные дома, аспекты в коде), `newsDigest.ts` (Sonnet+web_search, кэш), `letterEngine.ts` (2 прохода Opus).
- `scheduleLetters` (cron 15м), `processLetterJob` (воркер: генерит → +1✦ → advance расписания → email), `generateLetterNow` (синхронный триггер/сэмпл).
- **Проверено на реальной карте Boris**: residence=Gurnee, локальные новости, COGS $0.15, ~90% маржа.

**Фаза 3 — Доставка ✅ (v2.7.0)**
- Callables: `listLetters/getLetter/markLetterRead/setLetterFeedback/answerLetterQuestion` (тап→досье, бесплатно)/`askInLetter` (✦1→оракул).
- UI: лента «Letters» (`/profile/:id/letters`) — DOMPurify HTML, кнопки-вопросы, «спросить за ✦1», фидбек, кнопка «Generate a letter».
- Email-тизер через Resend (`sendLetterTeaserEmail`) — включится, когда задан секрет `RESEND_API_KEY`.

**Фаза 4 — Биллинг ✅ (v2.8.0)**
- `pricing.ts` (3×отчётов×$0.50; год=12 за 10), `subscribeAstrologer` (Stripe Checkout subscription mode), webhook (создание подписки + cancel/past_due/renewal), `getAstrologerStatus/cancel/pause/resume/setSubscriptionChannels`.
- UI: «Personal Astrologer» хаб (`/profile/:id/astrologer`) — найм (частота/период/каналы/имя), управление (пауза/возобновить/отмена).

**Фаза 5 — Приватность ◐**
- Готово: `forgetDossierData` (удаляет досье+факты+историю), `exportUserData` (GDPR), согласие на сенситив, сенситив-факты не используются без подтверждения. Хранение писем без лимита (как решено). РФ-данные не храним.
- Осталось: каскад полного удаления аккаунта (нет UI-точки удаления аккаунта).

**Фаза 6 — Рост/полировка ◐**
- Осталось: открыть бесплатное «пробное письмо» без флага (launch), дашборд метрик в админке, тонкая отладка промптов. Dunning по сути закрыт вебхуком Stripe.
