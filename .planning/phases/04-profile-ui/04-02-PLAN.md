  <action>
1. **Install geo-tz:**
   ```bash
   cd functions && npm install geo-tz
   ```

   **IMPORTANT:** geo-tz v8+ is ESM-only. Since functions use `"module": "commonjs"` in tsconfig, you must use **dynamic import**:
   ```typescript
   const { find } = await import("geo-tz");
   ```
   If dynamic import doesn't work with the current tsconfig, try:
   - Option A: Install geo-tz v7 instead (`npm install geo-tz@7`) which supports CJS
   - Option B: Use `require()` if v7
   Pick whichever works — the goal is a working `getTimezoneFromCoords(lat, lng)` function.

2. **Create `functions/src/utils/timezone.ts`:**
   ```typescript
   /**
    * Resolve IANA timezone from coordinates using geo-tz.
    * Uses dynamic import because geo-tz v8 is ESM-only.
    */
   export async function getTimezoneFromCoords(lat: number, lng: number): Promise<string> {
     const { find } = await import("geo-tz");
     const results = find(lat, lng);
     return results[0] || "UTC";
   }
   ```
   - If v8 dynamic import doesn't compile, fall back to v7 with static import
   - The function must return a valid IANA timezone string

3. **Update types — make timezone optional in CreateProfilePayload:**

   **`functions/src/types/index.ts`:**
   - Change `CreateProfilePayload.timezone` from `string` to `string | undefined` (optional):
     ```typescript
     timezone?: string; // Optional — server resolves from lat/lng if not provided
     ```

   **`web/src/types/index.ts`:**
   - Same change: `timezone?: string;`

4. **Update validation — `functions/src/validation/profile.ts`:**
   - In `validateCreateProfilePayload`: Change the timezone check from required to optional.
     - Instead of: `if (!isNonEmptyString(payload.timezone))` → error
     - Change to: `if (payload.timezone !== undefined && !isNonEmptyString(payload.timezone))` → error
     - i.e., timezone can be omitted, but if provided must be a non-empty string
   - `validateUpdateProfilePayload` already handles timezone as optional — no change needed

5. **Update `functions/src/api/createProfile.ts`:**
   - Import `getTimezoneFromCoords` from `../utils/timezone`
   - After validation passes, before calling `profileService.createProfile`:
     - If `data.timezone` is not provided (undefined or empty):
       - Call `const timezone = await getTimezoneFromCoords(data.lat, data.lng)`
       - Set `data.timezone = timezone`
     - If timezone IS provided, use as-is (trust client or verify later)
   - Pass the (possibly enriched) data to profileService.createProfile

6. **Update `functions/src/api/updateProfile.ts`:**
   - Import `getTimezoneFromCoords` from `../utils/timezone`
   - After ownership check, before calling profileService.updateProfile:
     - If lat OR lng changed (present in updateFields) and timezone is NOT in updateFields:
       - Resolve timezone: determine the lat/lng to use (from updateFields if present, else from existing profile)
       - Call `const timezone = await getTimezoneFromCoords(lat, lng)`
       - Add `timezone` to updateFields
   - This ensures timezone stays in sync when coordinates change

7. **Verify build:**

3. **Create `web/src/components/PlaceSearch.tsx`:**
   - **Photon API integration** with debounced typeahead:
     - Props: `onSelect: (place: { name: string; lat: number; lng: number }) => void`
     - Optional prop: `initialValue?: string` (for edit mode, shows existing place name)
     - State: `query: string`, `results: PhotonFeature[]`, `isOpen: boolean`, `loading: boolean`

   - **Photon types (inline):**
     ```typescript
     interface PhotonProperties {
       name?: string;
       city?: string;
       state?: string;
       country?: string;
       countrycode?: string;
     }

     interface PhotonFeature {
       geometry: { coordinates: [number, number] }; // [lon, lat] — NOTE: lon first!
       properties: PhotonProperties;
     }
     ```

   - **Search function:**
     - Fetch from `https://photon.komoot.io/api?q=${query}&limit=5&lang=en`
     - Parse response as GeoJSON FeatureCollection
     - Extract features array

   - **Debounce + AbortController pattern:**
     - Track `AbortController` via useRef
     - On input change:
       - Abort previous request
       - If query < 3 chars: clear results, return
       - Set 300ms timeout
       - On timeout: fetch Photon, update results if not aborted
     - Use `useEffect` cleanup to abort on unmount

   - **Result display:**
     - Absolute-positioned dropdown below the input
     - Each result shows: name, city/state/country formatted
     - Format display: `${name}, ${state || ''}, ${country || ''}` (filter empties)
     - On click/select:
       - Extract coordinates: `const [lon, lat] = feature.geometry.coordinates` (lon first!)
       - Build display name from properties
       - Call `onSelect({ name: displayName, lat, lng: lon })`
       - Set input value to display name
       - Close dropdown

   - **Click outside to close:** Use ref + effect for click outside detection
