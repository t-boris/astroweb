## Statement

A checklist in the repository documents how GA4 is set up and why the always-sent server-side events are legally defensible, and the GA4 funnel exploration exists and is documented.

## Acceptance Criteria

- [ ] docs/ga4-setup-checklist.md lists: the GA4 property and web stream, the Firebase link, the Measurement Protocol secret name and where it lives (never its value), key events, the BigQuery export link step, the internal-traffic filter on traffic_type = internal, Search Console linking and the optional Looker Studio dashboard.
- [ ] The checklist contains the legal reasoning for sending server-side purchase and subscription events without consent with a pseudonymous client_id derived from the transaction id, and states it is linkable to the Stripe/Firestore payment record.
- [ ] The checklist covers keeping the consent state in the Stripe subscription metadata and applying it to later renewal and cancel events, including that existing subscriptions without that metadata are treated as not consented.
- [ ] A GA4 funnel exploration 'Visit -> Profile created -> Chart viewed -> Paywall viewed -> Checkout started -> Purchase' (events session_start/page_view, profile_created, chart_viewed, paywall_viewed, begin_checkout, purchase) exists in the GA4 property and its name and steps are recorded in the checklist.
- [ ] The events listed on the privacy pages, the events in REQ-005 and the events in the checklist are the same set.
