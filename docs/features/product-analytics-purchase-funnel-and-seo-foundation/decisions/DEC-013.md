## Context

The repository's only workflow (.github/workflows/firebase-deploy.yml) runs on push to main. Its latest run, 2026-10-12 on 'Fixed git ignore', failed: 'Secret environment variable overlaps non secret environment variable: STRIPE_SECRET_KEY' (the workflow writes STRIPE_SECRET_KEY into functions/.env while the functions also bind it as a secret) and a Cloud Build npm error ('Cannot read properties of null (reading edgesOut)'). A pull request therefore gets no CI check. Production has been deployed manually with npm run deploy (memory note prod-environment). Approved by the owner on 2026-10-12.

## Alternatives

1. No PR-check workflow: the PR has no checks and local output is the evidence
2. Also repair firebase-deploy.yml in this change

## Decision

Add .github/workflows/ci.yml, triggered on pull_request and push to branches other than main, running npm ci, the functions build and tests, and the web build on Node 22. Lint is left out because web has 9 pre-existing errors. firebase-deploy.yml is not changed here; its failure is pre-existing and out of scope. This release is deployed manually: npm run build:functions, then npm run deploy. web/package.json goes from 2.19.1 to 2.20.0 (minor, new feature) before the final commit.

## Reason

The definition of done needs a real CI result on the PR; a read-only check workflow is low risk and does not touch deployment. Deploying manually follows how production was deployed so far.

## Consequences

Merging to main will still trigger the broken auto-deploy workflow, so main will show a red 'Deploy to Firebase' run until it is fixed separately; this is reported, not fixed here. A follow-up should repair firebase-deploy.yml (drop STRIPE_* from the generated .env, resolve the Cloud Build npm error).
