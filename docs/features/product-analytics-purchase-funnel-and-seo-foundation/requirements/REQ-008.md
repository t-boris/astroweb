## Statement

The HTML that Firebase Hosting serves for /, /ru, /privacy and /ru/privacy contains that page's own SEO tags without running JavaScript, and private routes are served with noindex.

## Acceptance Criteria

- [ ] A plain HTTP GET (no JavaScript) of /, /ru, /privacy and /ru/privacy returns a document with its own title, meta description, self-referencing canonical, og:title, og:description, og:url, og:locale, twitter:card and twitter:title, and the four pages' titles and descriptions are pairwise different.
- [ ] Each of the four pages has hreflang links for en, ru and x-default that point at its counterpart pair.
- [ ] The landing pages / and /ru contain JSON-LD structured data (a WebSite or WebApplication object with the page language and URL).
- [ ] GET /robots.txt returns 200 text with a Sitemap line and does not block / or /ru; GET /sitemap.xml returns 200 XML listing exactly /, /ru, /privacy and /ru/privacy.
- [ ] GET /admin, /account and /profile/new return the SPA with the response header X-Robots-Tag: noindex, and the client also sets meta robots noindex on those routes.
- [ ] Visiting /ru (or /ru/privacy) sets the UI language to Russian and visiting / (or /privacy) sets it to English; the language switcher on a public page navigates to the counterpart URL.
- [ ] A unit test of the route metadata checks that every public route has a unique title and description and a complete hreflang set.
- [ ] The generated HTML files are produced by npm run build:web and are present in web/dist.
