## Context

Found while reading ProfileDetail.tsx: TabsList renders nine tabs and no "premium" trigger; TabsContent value="premium" is reached by setActiveTab or ?tab=premium.

## Alternatives

1. Add a new Premium tab trigger (a visible UI change that was not asked for)
2. Keep native title next to the bubble
3. Leave plain-text terms out of the tab order and give keyboard users no way to open their bubbles

## Decision

(1) The Premium panel has no tab label in the tab list (it opens from the stars pill and from locked features), so its help bubbles go on the store heading and the stars balance. (2) Where a HelpBubble is attached to an icon-only button, the native title attribute is removed (the bubble replaces it) and aria-label stays. (3) A non-actionable element that gets a bubble becomes keyboard-focusable (tabindex 0) so the bubble opens on focus; actionable elements are already focusable.

## Reason

(1) REQ-002 lists "premium content" as a tab but ProfileDetail renders no tab trigger for it. (2) A native title tooltip next to a custom bubble would show two overlapping tooltips. (3) REQ-005 requires opening on keyboard focus; hover-only text would otherwise be unreachable by keyboard.

## Consequences

Dense tables add tab stops for keyboard users (one per term). Acceptable for the first iteration; the cost is noted in the review.
