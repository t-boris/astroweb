## Context

DEC-001 says the webhook always sends purchase and subscription events to GA4, and DEC-006 excludes livemode=false purchases from the Business tab so revenue stays honest. Neither says what to do with Stripe test-mode events (livemode=false), which would otherwise appear as real purchases in the production GA4 property. Discovered while implementing the webhook; same reasoning as DEC-006, applied to GA4.

## Alternatives

1. Send test-mode events too and filter them in GA4 later (pollutes the funnel and revenue until filtered)
2. Send test-mode events to the Measurement Protocol debug endpoint only

## Decision

The webhook sends no GA4 event for a Stripe event with livemode = false. 'Always sent' in DEC-001 applies to live-mode events. Test-mode purchases are still recorded in Firestore with livemode = false. An unpaid (asynchronous) checkout session sends nothing until it is paid.

## Reason

Keeps GA4 revenue and funnel counts equal to real customers, consistent with DEC-006, at no cost to real users.

## Consequences

A test-mode checkout cannot be used to see an event arrive in GA4 end to end. Verification of the payload uses unit tests and the GA4 validation endpoint (/debug/mp/collect). If the owner wants test traffic in GA4 later, it needs a separate decision (for example a dedicated test property).
