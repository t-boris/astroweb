## Context

While checking the specification against the code, several points were open or contradicted the code: askOracle, askRelationship, unlockFeature and createCheckoutSession accept a deviceId-only caller (REQ-004 and REQ-006 require an account); Layout.handleSignIn reloads the page, which cancels an action that should continue after sign-in; oracleHistory contains entries with channel 'letter' as well as 'web'; one deep text is kept per block on the device, regardless of language. The owner approved the plan and these defaults on 2026-10-12.

## Alternatives

1. Show only channel 'web' entries in the Oracle history
2. Keep one deep text per block and language

## Decision

1) Three new callables: getProfileContent (all content of a profile for its owner), uploadLocalContent (account-authenticated only; only for profiles whose ownerUid equals the caller's uid; content-hash deduplication; size limits; never touches stars or unlock flags; server content wins on conflict) and deleteProfileContentItem. askOracle, askRelationship, unlockFeature and createCheckoutSession answer 'unauthenticated' before any charge when the caller has no account. 2) A deep text is stored once per interpretation block (as on the device today), with its language as a field; a signed-in owner's deepenInterpretation call persists it. An anonymous owner of an old unlocked profile still generates texts, but they stay in the browser (DEC-004). 3) The Oracle history shows every oracleHistory entry, including those from astrologer letters. 4) The sign-in gate opens the Google popup synchronously from the click, then runs claimProfiles, then continues the original action, with no page reload; the 'Sign in to save' notice is shown in the profile list. 5) Stars left on an anonymous device wallet can be spent only after sign-in; the wallets merge on sign-in. 6) Tests use no new libraries (the Firestore rules are checked by a test of the rules text); release version 2.21.0; deployment by the repaired CI when the pull request is merged.

## Reason

These are the smallest choices that satisfy REQ-001 to REQ-008 and DEC-001 to DEC-008 without new libraries or a change of architecture.

## Consequences

Existing anonymous users who hold stars cannot spend them until they sign in. The wallet merge on sign-in is the existing claimProfiles behaviour. A reading generated while the server write fails is returned with persisted=false and kept locally until the next upload.
