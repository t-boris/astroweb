## Statement

Deep interpretation texts generated for a profile must be persisted on the server and shown on any device to the profile owner, without spending stars again. Deep texts that exist only in a browser's localStorage are uploaded to the server once, automatically, only for a signed-in owner whose profile is already claimed (ownerUid matches the account, i.e. after claimProfiles completes); the upload endpoint requires account authentication and rejects deviceId-only callers. Anonymous users' local-only deep texts stay in the browser until they sign in with Google (accepted risk: they are lost if the browser storage is cleared or the browser is switched before sign-in).

## Acceptance Criteria

- [ ] A deep text generated on device A is shown on device B for the same account without a new star spend or regeneration.
- [ ] Clearing browser storage does not remove any deep text that has been stored on the server.
- [ ] Deep texts that existed only in localStorage before release become available on other devices after the signed-in owner opens the claimed profile (ownerUid set to that account) once on the original device.
- [ ] The one-time upload of local-only deep texts starts only after claimProfiles has completed for the signed-in account on that device.
- [ ] The upload endpoint rejects calls authenticated only by deviceId, and no deep text is stored from such a call.
- [ ] The upload endpoint rejects uploads for profiles whose ownerUid is missing or does not match the calling account.
- [ ] For an anonymous (deviceId) user, local-only deep texts are not uploaded and remain in that browser's localStorage until the user signs in with Google.
