<task type="auto">
  <name>Task 1: Implement createProfile, listProfiles, and getProfile Cloud Functions</name>
  <files>functions/src/api/createProfile.ts, functions/src/api/listProfiles.ts, functions/src/api/getProfile.ts, functions/src/index.ts</files>
  <action>
Create individual function files in `functions/src/api/` and wire them up in index.ts.

1. **functions/src/api/createProfile.ts** — `onCall` Gen 2:
   - Import `onCall`, `HttpsError` from `firebase-functions/v2/https`
   - Import validation from `../validation/profile`
   - Import profile service from `../services/profile`
   - Extract `data` from request
   - Run `validateCreateProfilePayload(data)` — if errors, throw `HttpsError("invalid-argument", ...)` with first error message
   - Call `profileService.createProfile(data)` with the validated payload
   - Return the created Profile object
   - Wrap in try/catch — unexpected errors throw `HttpsError("internal", "Failed to create profile")`

2. **functions/src/api/listProfiles.ts** — `onCall` Gen 2:
   - Extract `ownerDeviceId` from request data
   - Validate ownerDeviceId is non-empty string — if not, throw `HttpsError("invalid-argument", "ownerDeviceId is required")`
   - Call `profileService.listProfilesByOwner(ownerDeviceId)`
   - Return `{ profiles: Profile[] }`

3. **functions/src/api/getProfile.ts** — `onCall` Gen 2:
   - Extract `profileId` and `ownerDeviceId` from request data
   - Validate both are non-empty strings
   - Call `profileService.getProfileById(profileId)`
   - If null → throw `HttpsError("not-found", "Profile not found")`
   - **Ownership check:** If `profile.ownerDeviceId !== ownerDeviceId` → throw `HttpsError("permission-denied", "Access denied")`
   - Return the Profile object

4. **Update functions/src/index.ts:**
   - Remove the hello function
   - Re-export all three functions:
     ```typescript
     export { createProfile } from "./api/createProfile";
     export { listProfiles } from "./api/listProfiles";
     export { getProfile } from "./api/getProfile";
     ```
   - Keep `initializeApp()` at the top

**Error handling pattern for ALL functions:**
- Validation errors → `HttpsError("invalid-argument", message)`
- Not found → `HttpsError("not-found", message)`
- Ownership mismatch → `HttpsError("permission-denied", "Access denied")`
- Unexpected errors → `HttpsError("internal", "An unexpected error occurred")`
- Do NOT expose internal error details to client in production

**Gen 2 import pattern:** `import { onCall, HttpsError } from "firebase-functions/v2/https"` — do NOT use Gen 1 imports.

  <files>functions/src/api/updateProfile.ts, functions/src/api/deleteProfile.ts, functions/src/index.ts</files>
  <action>
1. **functions/src/api/updateProfile.ts** — `onCall` Gen 2:
   - Extract `profileId` and update data from request data
   - Validate profileId is non-empty string
   - Run `validateUpdateProfilePayload(data)` — if errors, throw `HttpsError("invalid-argument", ...)`
   - **Ownership check first:** Fetch profile by ID, verify `ownerDeviceId` matches
   - If profile not found → throw `HttpsError("not-found", "Profile not found")`
   - If ownership mismatch → throw `HttpsError("permission-denied", "Access denied")`
   - Extract update fields (everything from data except `ownerDeviceId` and `profileId`)
   - Call `profileService.updateProfile(profileId, updateFields)`
   - Return the updated Profile object

2. **functions/src/api/deleteProfile.ts** — `onCall` Gen 2:
   - Extract `profileId` and `ownerDeviceId` from request data
   - Validate both are non-empty strings
   - **Ownership check first:** Fetch profile by ID, verify `ownerDeviceId` matches
   - If profile not found → throw `HttpsError("not-found", "Profile not found")`
   - If ownership mismatch → throw `HttpsError("permission-denied", "Access denied")`
   - Call `profileService.deleteProfile(profileId)`
   - Return `{ success: true }`

3. **Update functions/src/index.ts** — Add exports:
   ```typescript
   export { updateProfile } from "./api/updateProfile";
   export { deleteProfile } from "./api/deleteProfile";
   ```

**Ownership enforcement pattern (consistent across all write operations):**
```
1. Validate input
2. Fetch existing profile
3. Check ownerDeviceId matches
4. Perform operation
5. Return result
```

This "fetch then check" pattern ensures ownership is ALWAYS verified before any mutation.

Do NOT add rate limiting here — that's Phase 7 (production readiness). Focus on correct CRUD with ownership.
