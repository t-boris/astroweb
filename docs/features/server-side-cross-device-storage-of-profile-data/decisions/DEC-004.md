## Context

F-001: REQ-004 allows uploading local Oracle history only after sign-in and claim, while REQ-007/DEC-002 say upload happens whenever the 'owner' opens the profile, and an anonymous deviceId holder also counts as owner under current ownership rules (functions/src/services/owner.ts). This left unclear which authentication the upload endpoint accepts and whether legacy paid content could end up stored under device-owned profiles, contrary to DEC-001's intent that paid content is account-bound.

## Alternatives

1. Any owner, including anonymous deviceId owners, may upload; server-stored content moves with the profile when it is claimed (requires rewriting REQ-004, dual auth on the endpoint, extra volume/rate limits for anonymous calls).
2. Mixed: deep texts and compatibility readings uploadable by any owner including anonymous; Oracle history only by signed-in users per REQ-004 (per-content-type auth rules, more complex upload logic and tests).

## Decision

The one-time upload of local-only content (deep interpretation texts, Oracle history, compatibility readings) is performed only for a signed-in caller and only for profiles that already have ownerUid matching that account, i.e. after claimProfiles. The upload endpoint requires account authentication and rejects deviceId-authenticated calls. Anonymous users' local content stays in the browser until they sign in; the DEC-003 banner encourages sign-in.

## Reason

Keeps all server-stored paid content bound to an account, consistent with DEC-001 and REQ-004; the endpoint needs a single authentication scheme, which simplifies security and abuse protection; matches the existing server behaviour where oracleHistory is recorded only for signed-in users.

## Consequences

REQ-007 is clarified: 'owner' means a signed-in user whose profile is already claimed (ownerUid set); add acceptance criterion that the upload endpoint rejects deviceId-only callers and that upload runs after claimProfiles completes. REQ-004 unchanged. Accepted risk: an anonymous user who clears browser storage or switches browser before signing in loses legacy local-only paid content; DEC-003 banner is the mitigation.
