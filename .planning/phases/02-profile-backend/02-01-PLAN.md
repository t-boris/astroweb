<task type="auto">
  <name>Task 2: Create profile payload validation module</name>
  <files>functions/src/validation/profile.ts</files>
  <action>
Create `functions/src/validation/profile.ts` with pure validation functions. These are stateless, no Firestore dependency — pure input → errors mapping.

1. **validateCreateProfilePayload(data: unknown): ApiError[]**
   Validate all required fields for profile creation:
   - `ownerDeviceId`: must be non-empty string
   - `name`: must be non-empty string, max 100 chars
   - `birthDate`: must be string matching YYYY-MM-DD format (regex `^\d{4}-\d{2}-\d{2}$`), parse with Date to verify it's a valid date
   - `birthTime`: if provided and not null, must match HH:mm format (regex `^\d{2}:\d{2}$`), hours 0-23, minutes 0-59
   - `timeUnknown`: must be boolean
   - `birthPlace`: must be non-empty string, max 200 chars
   - `lat`: must be number, range -90 to 90
   - `lng`: must be number, range -180 to 180
   - `timezone`: must be non-empty string (basic check — full IANA validation is complex, defer)
   Return array of ApiError objects (empty = valid). Each error includes `field` name.

2. **validateUpdateProfilePayload(data: unknown): ApiError[]**
   Validate partial update — only check fields that are present:
   - `ownerDeviceId`: REQUIRED (always needed for ownership)
   - All other fields: if present, apply same rules as create
   - At least one field besides ownerDeviceId must be provided (otherwise nothing to update)

3. **Helper: isNonEmptyString(val: unknown): val is string**
   Type guard for non-empty string validation.

4. **Helper: isValidDate(val: string): boolean**
   Validates YYYY-MM-DD is a real date (not just format — e.g., reject 2025-02-30).

Import ApiError from types. Use explicit type narrowing — do NOT use `any`. Use `unknown` for input parameters and narrow with type guards.

Do NOT install any validation library (Zod, Joi, etc.) — hand-roll for these simple checks. The validation functions are pure and easily testable.
  </action>

<task type="auto">
  <name>Task 3: Create profile Firestore service module</name>
  <files>functions/src/services/profile.ts</files>
  <action>
Create `functions/src/services/profile.ts` — a thin wrapper around Firestore admin SDK operations for the profiles collection. This module owns all Firestore interactions for profiles.

1. **Collection reference:**
   - Use `getFirestore()` from `firebase-admin/firestore` (admin SDK, not client SDK)
   - Collection name: `"profiles"`
   - Do NOT call `initializeApp()` here — it's called once in index.ts

2. **createProfile(payload: CreateProfilePayload): Promise&lt;Profile&gt;**
   - Generate a Firestore document with auto-ID (`collection.add()` or `doc().set()`)
   - Set `createdAt` and `updatedAt` to current ISO timestamp (`new Date().toISOString()`)
   - Return the full Profile object (including generated `id`)
   - Store data as plain object (no Firestore Timestamp — use ISO strings for portability)

3. **getProfileById(id: string): Promise&lt;Profile | null&gt;**
   - Fetch document by ID
   - Return Profile or null if not found
   - Include document ID as `id` field in returned object

4. **listProfilesByOwner(ownerDeviceId: string): Promise&lt;Profile[]&gt;**
   - Query profiles where `ownerDeviceId` matches
   - Order by `createdAt` descending (newest first)
   - Return array of Profile objects

5. **updateProfile(id: string, updates: Partial&lt;Omit&lt;Profile, "id" | "ownerDeviceId" | "createdAt"&gt;&gt;): Promise&lt;Profile&gt;**
   - Update only provided fields + set `updatedAt` to current timestamp
   - Use Firestore `update()` method
   - Return updated full Profile (re-fetch after update)
   - Throw if document doesn't exist

6. **deleteProfile(id: string): Promise&lt;void&gt;**
   - Delete document by ID
   - No error if already deleted (idempotent)

Import types from `../types/index`. Use `FieldValue.delete()` only if needed for field removal — not expected in MVP.

Do NOT add any caching, batching, or transactions — keep it simple for MVP.
  </action>
