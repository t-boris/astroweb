## Context

REQ-001 and REQ-003 and plan I-3 assumed a house-system toggle and house systems "shown" in the UI. The code always requests "koch" (ProfileDetail.tsx) and nothing displays houses.system; the server can fall back to whole-sign at extreme latitudes (functions/src/astro/chart.ts).

## Alternatives

1. Add a real house-system selector (placidus / koch / whole-sign) - a separate feature touching chart fetch, caching and interpretations
2. Skip house systems entirely and remove them from REQ-001 and REQ-003

## Decision

No house-system selector is added. The Houses tab shows the house system the chart actually uses (ChartResult.houses.system: Koch by default, Whole Sign when the server falls back) as a small read-only label with a help bubble. Help texts are written for all three systems (Placidus, Koch, Whole Sign). Wherever the spec says "house-system toggle" it now means this label.

## Reason

Answer to Q-007 (A, 2026-10-13). The app has no toggle and never shows the system; a selector would change which chart is fetched and cached and is a separate feature. The label makes the house-system requirement testable without that.

## Consequences

One small UI addition (the label) in the Houses tab; REQ-001 AC1 and REQ-003 AC2 are reworded from "toggle" to "label"; plan I-3 follows. A future selector can reuse the same help keys.
