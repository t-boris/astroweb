## Statement

Help bubbles shall use a single consistent component across the app, open on hover/keyboard focus on pointer devices and on tap on touch devices — via a small '?' icon where tapping the element already performs an action — and be always enabled and accessible to keyboard and screen-reader users.

## Acceptance Criteria

- [ ] One shared help component is used on all covered screens.
- [ ] On pointer devices help opens on hover after a short delay and on keyboard focus, and closes on Escape or pointer leave.
- [ ] On touch devices actionable elements (tabs, filters, buttons) show a '?' icon that opens help without triggering the element's action; non-actionable elements open help on tap; tapping outside closes it.
- [ ] Help content is announced by screen readers (accessible description or dialog semantics).
- [ ] Bubbles stay within the viewport on mobile widths.
- [ ] There is no setting to disable help, and no analytics event is emitted on opening help.
