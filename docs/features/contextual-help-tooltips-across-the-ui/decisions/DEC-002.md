## Context

Responsive UI is a project requirement; hover is unavailable on touch, and many target elements are actionable.

## Alternatives

1. Hover on desktop, long-press on touch
2. Always-visible '?' icon next to every element on all devices

## Decision

Hybrid: on pointer devices help opens on hover/focus of the element itself; on touch devices a small '?' icon is shown only where tapping the element already performs an action, otherwise tapping the element opens help.

## Reason

Keeps the desktop UI clean and avoids hijacking taps on tabs and filters on mobile.

## Consequences

Two interaction modes must be implemented and tested; actionable elements need a separate touch affordance.
