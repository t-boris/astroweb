## Context

Deploying this release failed for every function with 'npm error Cannot read properties of null (reading edgesOut)' in Cloud Build. The same error broke the CI auto-deploy before this feature. Reproduced locally with a plain `npm install` of functions/package.json: removing the vitest devDependency removes the crash; vitest 4.0.18 and 3.2.4 resolve fine, vitest 4.1.0 and later crash, and the range ^4.0.18 floats to 4.1.11. Approved by the owner on 2026-10-12.

## Alternatives

1. Move vitest to the repo root devDependencies so Cloud Build never sees it
2. Upgrade to vitest 5
3. Deploy from another environment

## Decision

functions/package.json declares \"vitest\": \"4.0.18\" (exact, no caret). That is the version already in the root lockfile and used by the tests, so no upgrade and no new library. It ships in its own small pull request.

## Reason

Smallest change that restores installability of the functions in Cloud Build while keeping tests and layout as they are.

## Consequences

vitest in functions no longer follows 4.x automatically; moving to 4.1+ needs the npm resolver crash to be resolved first. firebase-deploy.yml still has its separate STRIPE_SECRET_KEY / .env overlap problem (DEC-013) and stays untouched.
