## Context

The owner has no OpenAI or Gemini key ready yet (answer in chat, 2026-10-18). Binding a secret that does not exist in Secret Manager fails the functions deploy.

## Alternatives

1. Wait with the merge until both real keys exist
2. Bind the secrets only after the keys exist (two releases)

## Decision

Before the merge, OPENAI_API_KEY and GEMINI_API_KEY are created in Secret Manager with the placeholder value "unset". A provider counts as configured only when its key has the provider's key format (OpenAI "sk-…", Gemini "AIza…", Claude "sk-ant-…" as today); otherwise its models are shown as unavailable and cannot be saved. Adding the real key later is a new secret version plus a redeploy or instance restart, with no code change.

## Reason

Answer of the owner on keys (option "not yet"), 2026-10-18; keeps the deploy green and the providers visibly off until keys exist.

## Consequences

Until the real keys are added, OpenAI and Gemini can only be verified with mocked SDKs in tests; the paid test run per provider happens after the owner adds the keys.
