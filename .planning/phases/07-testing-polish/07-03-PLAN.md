  <name>Task 1: Chart SVG responsive container + table horizontal scroll</name>
  <files>web/src/components/chart/NatalChart.tsx, web/src/components/chart/PlanetsTable.tsx, web/src/components/chart/AspectsTable.tsx, web/src/components/chart/AspectFilters.tsx</files>
  <action>
1. **Make NatalChart SVG responsive:**

   The SVG already uses `viewBox="0 0 1000 1000"` which scales naturally. The issue is the container around it. Currently the SVG likely fills its parent container without constraints.

   - Wrap the SVG in a responsive container with `max-w-[600px] mx-auto w-full` — this constrains the chart to 600px max on desktop while scaling down on mobile.
   - Ensure the SVG has `width="100%" height="auto"` (or equivalent via `className="w-full h-auto"`).
   - The SVG's `viewBox="0 0 1000 1000"` handles the actual scaling — no need to change internal coordinates.

2. **Make AspectFilters responsive:**

   The 5 toggle buttons are in a horizontal flex row. On narrow screens they may overflow.

   - Change from `flex` to `flex flex-wrap` so buttons wrap to a second row on small screens.
   - Add `gap-2` for consistent spacing when wrapped.
   - Consider making each button slightly smaller on mobile: add `text-xs sm:text-sm` to button text.

3. **Make PlanetsTable horizontally scrollable:**

   Wrap the Table component in an overflow container:
   ```tsx
   <div className="overflow-x-auto">
     <Table>
       {/* ... existing table content ... */}
     </Table>
   </div>
   ```

   Also add `min-w-[400px]` to the Table to ensure columns don't get too compressed before scroll kicks in.

4. **Make AspectsTable horizontally scrollable:**

   Same pattern as PlanetsTable:
   ```tsx
   <div className="overflow-x-auto">
     <Table className="min-w-[500px]">
       {/* ... existing table content ... */}
     </Table>
   </div>
   ```

   The aspects table has 5 columns (bodyA, aspect, bodyB, orb, exactness) so it needs a slightly wider minimum.
  </action>

<task type="auto">
  <name>Task 2: Tabs mobile adaptation + overall responsive polish</name>
  <files>web/src/pages/ProfileDetail.tsx, web/src/index.css</files>
  <action>
1. **Fix tab bar for mobile:**

   The current tab bar uses `grid grid-cols-4` which compresses 4 tabs on narrow screens. The labels ("Interpretation" is long) will get clipped or overflow.

   Change the TabsList to use horizontal scroll on mobile:
   ```tsx
   <TabsList className="flex w-full overflow-x-auto">
     <TabsTrigger value="chart" className="flex-1 min-w-fit">{t("tabs.chart")}</TabsTrigger>
     <TabsTrigger value="planets" className="flex-1 min-w-fit">{t("tabs.planets")}</TabsTrigger>
     <TabsTrigger value="aspects" className="flex-1 min-w-fit">{t("tabs.aspects")}</TabsTrigger>
     <TabsTrigger value="interpretation" className="flex-1 min-w-fit">{t("tabs.interpretation")}</TabsTrigger>
   </TabsList>
   ```

   This keeps tabs in a single row but allows scrolling if needed. `min-w-fit` ensures tab labels aren't truncated. On desktop, `flex-1` makes them fill the width evenly.

2. **Birth data card responsive:**

   The `grid grid-cols-[auto_1fr]` definition list works on mobile but check spacing. Add responsive padding:
   ```tsx
   <dl className="grid grid-cols-[auto_1fr] gap-x-4 gap-y-2 text-sm">
   ```
   This is likely already fine. No change needed if it looks good.

3. **Action buttons responsive:**

   The `flex gap-2` row of action buttons (Edit, Delete, Back) should wrap on very narrow screens:
   ```tsx
   <div className="flex flex-wrap gap-2">
   ```

4. **Add responsive utilities to index.css:**

   Add a utility class for the scrollbar-hidden tab bar (prevent visible scrollbar on the tabs):
   ```css
   /* Hide scrollbar for tab navigation on mobile */
   .scrollbar-hidden {
     -ms-overflow-style: none;
     scrollbar-width: none;
   }
   .scrollbar-hidden::-webkit-scrollbar {
     display: none;
   }
   ```

   Apply `scrollbar-hidden` class to the TabsList: `className="flex w-full overflow-x-auto scrollbar-hidden"`.

5. **Page container responsive:**

   Check if the main layout container has appropriate padding for mobile. The Layout component should have `px-4 sm:px-6` or similar. If not, add responsive horizontal padding.

   In ProfileDetail, ensure the main container doesn't have excess whitespace on mobile. The `space-y-6` is fine for vertical spacing.

6. **Profile form (ProfileCreate) responsive verification:**

   The form already uses `max-w-lg mx-auto` which is responsive-friendly. The PlaceSearch dropdown should also work on mobile (it's a standard dropdown list). No changes needed unless `max-w-lg` is too narrow — check if it needs `px-4` for mobile edge padding. Add `px-4 sm:px-0` to the outer container if the form touches screen edges on mobile.
