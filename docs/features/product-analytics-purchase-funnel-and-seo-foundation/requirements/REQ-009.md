## Statement

Every spend of stars and every refund of a failed action is recorded in the starSpends collection atomically with the wallet change, labelled with the feature.

## Acceptance Criteria

- [ ] unlockFeature (interpretations, compatibility), askOracle, askRelationship and askInLetter each write one starSpends row {walletKey, feature, stars, createdAt} in the same Firestore transaction as the wallet debit.
- [ ] A refund after a failed generation writes a row with negative stars for the same feature, so net stars per feature never counts a failed action.
- [ ] An already-unlocked feature that is not charged again writes no row.
- [ ] A debit that fails with INSUFFICIENT_TOKENS writes no row.
- [ ] Feature labels are exactly: interpretations, compatibility, oracle, relationship, letter.
- [ ] Unit tests cover the ledger row shape, the refund sign and the no-charge cases.
