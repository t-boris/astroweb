## Statement

The /admin page has a Business tab, fed by a new adminStats callable that only the verified admin can call, showing money and usage KPIs computed from Firestore for a selectable period.

## Acceptance Criteria

- [x] adminStats rejects with permission-denied any caller who is not the verified admin account (same assertAdmin rule as the other admin callables), including an unauthenticated caller and a signed-in non-admin.
- [x] The Business tab offers the periods 7d, 30d, 90d and all; the callable takes the period and a grouping of day, week or month.
- [x] Revenue is reported per currency without conversion and equals the sum of purchases.amountTotal of live-mode purchases in that currency within the period.
- [x] A purchase is live-mode when its livemode field is true; when the field is absent it is live-mode only if the document id starts with cs_live_. Purchases with livemode false or an id starting cs_test_ are excluded.
- [x] The stripeWebhook writes livemode, walletKey and, when the wallet key is a uid, ownerUid onto every new purchases document.
- [x] Day, week and month buckets are computed in UTC; weeks start on Monday; a revenue series per currency is returned for the chosen grouping.
- [x] The tab shows purchase count, paying users and ARPPU (revenue / paying users, per currency); a paying user is the first available of purchase.ownerUid, profile.ownerUid, purchase.ownerDeviceId, profile.ownerDeviceId, counted once.
- [x] The tab shows the current number of astrologer subscriptions with status active, past_due and canceled.
- [x] The tab shows the number of profiles created in the period.
- [x] The tab shows net stars spent per feature in the period from the starSpends ledger, and states that ledger data starts at the release date.
- [x] Subscription charges are not part of the revenue figure.
- [x] Unit tests cover the period/bucket maths, the livemode derivation, the payer chain and the per-currency totals with a fixed set of purchase rows.
