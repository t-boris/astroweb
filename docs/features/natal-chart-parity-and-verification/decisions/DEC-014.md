## Context

computeNatalChart feeds prompts.ts, pdf.ts and transits.ts, which read chart.points and chart.aspects directly. pdf.ts iterates every point and aspect, and the overview puts changes to paid readings and PDF layouts out of scope. Plan items I-4 and I-5 say 'extend the chart result'. The owner was asked and chose additive fields (answer recorded in this conversation, 2026-11-21).

## Alternatives

1. Extend points and aspects in place and add an explicit legacy-subset filter in prompts.ts, pdf.ts and transits.ts: one array each, but it touches three services and carries more regression risk for paid output.

## Decision

points and aspects keep their current contents (the ten standard bodies, the five major aspects at the current orb, and ASC and MC as aspect endpoints when the birth time is known). New additive fields on ChartResult carry the added points (both lunar nodes, Black Moon Lilith, Chiron, Part of Fortune, Vertex), retrograde and speed data for every calculated point, and the shared expanded aspect set from DEC-011. The wheel, tables, aspect matrix and summaries read the new fields.

## Reason

AI prompts, premium PDFs and transits see the same data as before, so paid readings do not change and the scope exclusion holds. The profile views still share one calculated result.

## Consequences

The functions and web ChartResult types gain optional fields and stay in sync. Charts cached before this change lack the new fields, so the cache key gains a calculation version (REQ-005, I-8) and older entries are recalculated on read. Regression tests assert that points and aspects are unchanged for the existing reference charts.
