## Finding

External fact (to be verified against current GA4 docs): for web data streams, the GA4 Measurement Protocol requires client_id in every payload. Payloads without it are dropped, and the validation endpoint reports them as invalid. As written, the acceptance criterion would make every anonymous purchase disappear without any error. The spec has to say what to send instead, for example a random per-transaction pseudo client_id that is never stored or reused. The privacy page wording also has to match that choice.

> Without consent, the purchase event is still sent but contains no client_id, user_id or other identifier of the user.

## Possible interpretations

- Generate a random, single-use client_id per transaction (e.g. derived from nothing user-linked) so that GA4 accepts the hit
- Skip the event when there is no consent, which contradicts DEC-001

## Resolution

Строить client_id из Stripe session id детерминированно, например хешем. Повторы webhook дадут тот же client_id. — see DEC-005.
