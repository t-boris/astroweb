## Context

Plan I-6 and REQ-003 excluded "astrologer workspace screens (including AstrologerNotes)". In the code the only internal screen is Admin.tsx; AstrologerNotes is reached from AstrologerPanel and edited by the signed-in customer.

## Alternatives

1. Keep AstrologerNotes excluded as the plan says, and have the no-help check cover Admin and AstrologerNotes

## Decision

AstrologerNotes ("What your astrologer knows", /profile/:id/notes) is treated as an end-user screen and gets help bubbles (icon-only buttons, "needs your OK", interests, "Forget everything"). The "no help bubbles" check applies to Admin only (pages/Admin.tsx and components/admin/*). DEC-003's "astrologer workspace" is clarified: no such screen exists in the code.

## Reason

Answer to Q-008 (A, 2026-10-13). The page is the customer's own dossier, linked from the Astrologer panel; DEC-003's reason for excluding screens (internal users need no onboarding help) does not apply to it.

## Consequences

More end-user coverage (a few controls); REQ-003 AC4 and plan I-6 are reworded to Admin only; the automated "no help in Admin" check no longer lists AstrologerNotes.
