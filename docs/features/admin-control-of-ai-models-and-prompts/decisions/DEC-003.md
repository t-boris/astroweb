## Context

Model constants and prompt builders are scattered over anthropic.ts, letterEngine.ts, newsDigest.ts, factExtraction.ts and getForecast.ts; the feature must not change any answer until the admin changes something.

## Alternatives

1. Keep builders as they are and only make the model configurable (smaller, but prompts stay uneditable)
2. Move all prompt text to Firestore with no code defaults (a broken or deleted document would break the feature)

## Decision

A registry module defines every AI task (id, admin label, default model, default request limits, default prompt texts per language, allowed and required placeholders). The defaults are today's texts turned into templates. Each call site asks the registry for the effective settings (stored override or default) and renders the template with its data. A test proves that, with no override, every task produces exactly the same system and user text and request parameters as before. The internal continuation prompt stays in code and is not editable.

## Reason

One place to see and change AI behaviour; no silent behaviour change on release; the admin UI is generated from the registry instead of being hand-coded per task.

## Consequences

The prompt builders are refactored into templates plus data-building functions; existing prompt tests are kept and extended.
