## Context

F-002 identified an ambiguity in REQ-003. Its agreement criterion covers aspects shown in both the wheel and matrix, leaving eligibility across those views and the existing Aspects list unspecified.

## Alternatives

1. Use one expanded aspect set with different display defaults. The matrix opens with the full set, while the wheel and list open with the current subset and let users reveal the full set.
2. Calculate the matrix with expanded rules for point pairs, aspect types, and orbs. Keep the existing calculation rules for the wheel and list.

## Decision

The natal wheel, aspect matrix, and Aspects list use one expanded set of calculated aspects. Filters change only which aspects are visible.

## Reason

A shared calculation gives each aspect the same eligibility and values across the profile and makes the complete set verifiable in all three views.

## Consequences

Update REQ-003 to include the Aspects list and require all three views to use the shared result. With filters cleared, the views must show the same qualifying point pairs and aspect types. Acceptance tests must verify matching orb values and applying or separating status wherever applicable, and confirm that toggling filters changes only visibility.
