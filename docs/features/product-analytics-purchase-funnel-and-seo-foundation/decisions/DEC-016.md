## Context

DEC-010 delegated the Google-side setup to Claude through the MarkView browser. While doing it, the browser session had two Google accounts (the default boris@mobilemindai.com and t.boris@gmail.com, the owner of the Firebase project). Google asks the property owner for a 'User Data Collection Acknowledgement' before a Measurement Protocol API secret can be created, and warns that activating a data filter is irreversible and not retroactive.

## Alternatives

1. Create a new GA account for the property
2. Activate the Internal Traffic filter immediately
3. Skip the Measurement Protocol secret and send no server-side events

## Decision

The Firebase console was used as t.boris@gmail.com. Enabling Google Analytics on astroweb-dev created the GA4 property 'astroweb-dev' (property id 558657249) in the existing GA account MobileMindAI, with the web stream 'AstroWeb' (stream id 16114991436, measurement id G-0RFR9LGX0L) linked to the Firebase web app. The owner explicitly authorised Claude to accept the User Data Collection Acknowledgement on 2026-10-12. The Measurement Protocol API secret 'astroweb-stripe-webhook' lives only in Secret Manager as GA_API_SECRET and was transferred through the clipboard without being printed. Enhanced Measurement is off on the stream, so GA does not add history-change page views next to ours. The 'Internal Traffic' data filter stays in Testing until the owner confirms in GA4 that admin events arrive with traffic_type = internal, then it is activated (irreversible, not retroactive).

## Reason

Uses the account that owns the product's operator name, keeps the secret out of the repository and chat, and avoids an irreversible GA change before it is verified.

## Consequences

The checklist (docs/ga4-setup-checklist.md) lists activating the filter as an owner step. The measurement id is public and committed in web/.env.production and functions/.env.astroweb-dev. Rotating the secret means creating a new one in GA4 and running firebase functions:secrets:set GA_API_SECRET.
