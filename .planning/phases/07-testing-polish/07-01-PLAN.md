  <name>Task 1: Install Vitest + unit tests for pure astro and validation functions</name>
  <files>functions/package.json, functions/vitest.config.ts, functions/src/__tests__/astro-utils.test.ts, functions/src/__tests__/validation.test.ts</files>
  <action>
1. **Install Vitest in functions/ package:**
   Run `cd functions && npm install -D vitest` to add Vitest as dev dependency.

2. **Create `functions/vitest.config.ts`:**
   ```typescript
   import { defineConfig } from 'vitest/config';
   export default defineConfig({
     test: {
       globals: true,
       include: ['src/__tests__/**/*.test.ts'],
     },
   });
   ```
   Note: functions/ uses CJS (`module: "commonjs"` in tsconfig). Vitest handles this natively since it uses esbuild for transformation.

3. **Add test script to `functions/package.json`:**
   Add `"test": "vitest run"` and `"test:watch": "vitest"` to the scripts section.

4. **Create `functions/src/__tests__/astro-utils.test.ts`** — tests for pure functions:

   **angularDifference tests (from aspects.ts):**
   - `angularDifference(0, 180)` → 180 (opposition)
   - `angularDifference(350, 10)` → 20 (wrap-around)
   - `angularDifference(10, 350)` → 20 (reverse wrap-around)
   - `angularDifference(0, 0)` → 0 (same point)
   - `angularDifference(90, 270)` → 180 (opposition via wrap)
   - `angularDifference(180, 180)` → 0

   **detectAspect tests (from aspects.ts):**
   - Exact conjunction: `detectAspect("Sun", 100, "Moon", 100)` → type "conjunction", orb 0, exactness 1
   - Exact trine: `detectAspect("Sun", 0, "Moon", 120)` → type "trine", orb 0, exactness 1
   - Trine with orb: `detectAspect("Sun", 0, "Moon", 124)` → type "trine", orb 4, exactness ~0.33
   - No aspect: `detectAspect("Sun", 0, "Moon", 45)` → null (45° is not a major aspect)
   - Orb boundary: `detectAspect("Sun", 0, "Moon", 126)` → type "trine" (exactly 6° orb, exactness 0)
   - Beyond orb: `detectAspect("Sun", 0, "Moon", 127)` → null (7° is beyond 6° orb)
   - Opposition wrap-around: `detectAspect("Sun", 5, "Moon", 185)` → type "opposition"

   **detectAllAspects tests (from aspects.ts):**
   - 3 points forming known aspects: verify correct count and sorting by exactness
   - Empty array: returns empty array
   - Single point: returns empty array

   **longitudeToZodiac tests (from zodiac.ts):**
   - 0° → Aries, 0°
   - 30° → Taurus, 0°
   - 29.99° → Aries, ~29.99°
   - 90° → Cancer, 0°
   - 359.99° → Pisces, ~29.99°
   - Negative: -10° → Pisces, 20° (normalization)
   - Over 360: 370° → Aries, 10°

   **findHouseForLongitude tests (from houses.ts):**
   - Standard cusps (evenly spaced at 30° intervals starting at 0°): planet at 15° → house 1
   - Wrap-around: cusps where house 12 crosses 0°: planet at 355° → correct house
   - Boundary: planet exactly on a cusp → belongs to that house (not previous)

   **computeInputHash tests (from services/chart.ts):**
   - Same inputs → same hash (deterministic)
   - Different inputs → different hash
   - null birthTime → consistent (uses "NULL" placeholder)
   - Hash is valid SHA-256 hex string (64 chars, hex only)

5. **Create `functions/src/__tests__/validation.test.ts`** — tests for validation functions:

   **isNonEmptyString tests:**
   - "" → false
   - "hello" → true
   - "  " → false (trimmed)
   - null → false
   - undefined → false
   - 123 → false

   **isValidDate tests:**
   - "2025-01-15" → true
   - "2025-02-29" → false (not leap year)
   - "2024-02-29" → true (leap year)
   - "2025-13-01" → false (month 13)
   - "2025-01-32" → false (day 32)
   - "not-a-date" → false
   - "2025-1-1" → false (wrong format)

   **validateCreateProfilePayload tests:**
   - Valid complete payload → empty errors array
   - Missing ownerDeviceId → error with field "ownerDeviceId"
   - Missing name → error with field "name"
   - Name > 100 chars → error
   - Invalid birthDate format → error
   - Invalid birthTime format → error
   - timeUnknown not boolean → error
   - lat out of range (-91) → error
   - lng out of range (181) → error
   - null payload → error
   - birthTime null allowed → no error for birthTime field

   **validateUpdateProfilePayload tests:**
   - Valid partial update (ownerDeviceId + name) → empty errors
   - Missing ownerDeviceId → error
   - No updatable fields → error
   - Invalid field values → same validation as create

<task type="auto">
  <name>Task 2: Integration tests for computeNatalChart with reference birth data</name>
  <files>functions/src/__tests__/chart.test.ts</files>
  <action>
1. **Create `functions/src/__tests__/chart.test.ts`** — integration tests using computeNatalChart directly:

   **Reference chart: Albert Einstein**
   - birthDate: "1879-03-14"
   - birthTime: "11:30"
   - timeUnknown: false
   - lat: 48.4011 (Ulm, Germany)
   - lng: 9.9876
   - timezone: "Europe/Berlin"
   - houseSystem: "placidus"

   **Expected sign placements** (well-documented in astrological literature):
   - Sun: Pisces
   - Moon: Sagittarius
   - Mercury: Aries
   - Venus: Aries
   - Mars: Capricorn
   - Jupiter: Aquarius
   - Saturn: Aries
   - Uranus: Virgo
   - Neptune: Taurus
   - Pluto: Taurus

   **Tests:**

   a) **Correct structure:**
   - result has `meta`, `points`, `houses`, `aspects` properties
   - meta.houseSystem is "placidus"
   - meta.zodiac is "tropical"
   - meta.timeUsed is "11:30"
   - meta.timezoneUsed is "Europe/Berlin"
   - points has exactly 10 entries
   - houses.cusps has exactly 12 entries
   - houses.asc is a number (not null, since time is known)
   - houses.mc is a number (not null)
   - aspects is an array with at least 1 entry

   b) **Correct sign placements:**
   - For each of the 10 bodies, verify `point.sign` matches the expected sign listed above
   - This is the core accuracy test — if signs are correct, the ephemeris is working

   c) **Degree reasonableness:**
   - Each point.lon is between 0 and 360
   - Each point.degreeInSign is between 0 and 30
   - Each point.house is between 1 and 12

   d) **House assignments:**
   - All 10 points have non-null house values
   - All house numbers are 1-12
   - Houses cusps are all between 0 and 360
   - ASC is between 0 and 360
   - MC is between 0 and 360

   e) **Aspects:**
   - Each aspect has valid fields: a (string), b (string), type (one of 5 types), orb (number ≥ 0), exactness (0-1)
   - Aspects are sorted by exactness descending
   - No duplicate pairs (a-b should not also appear as b-a)

   f) **Reproducibility:**
   - Call computeNatalChart twice with same input
   - Results must be deeply equal (JSON.stringify comparison)

   g) **timeUnknown mode:**
   - Same Einstein data but timeUnknown: true
   - houses.asc is null
   - houses.mc is null
   - All points have house: null
   - Aspects do NOT include ASC or MC as participants

   h) **Whole Sign house system:**
   - Same Einstein data but houseSystem: "whole-sign"
   - meta.houseSystem is "whole-sign"
   - Houses cusps are exactly at 30° intervals (0, 30, 60, ... 330 — adjusted for ASC sign)
   - All 10 points still have valid house assignments

   **Import:** `import { computeNatalChart } from '../astro/chart';`

   **Note on sweph initialization:** The sweph module initializes Moshier ephemeris at module load via `set_ephe_path('')`. This happens automatically when chart.ts is imported, since it imports from ephemeris.ts which calls set_ephe_path at module level. No special setup needed in tests.
