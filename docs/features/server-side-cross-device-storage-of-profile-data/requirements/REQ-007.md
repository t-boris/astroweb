## Statement

When a signed-in owner opens a profile on a device whose localStorage holds deep texts, Oracle history or compatibility readings for that profile that are not yet on the server, the client must upload them once. Here "owner" means a signed-in account whose profile is already claimed, i.e. ownerUid is set to that account. The upload starts only after claimProfiles has completed. The upload endpoint requires account authentication and rejects callers authenticated only by deviceId. After the upload, the content is read from the server. Anonymous users' local-only content stays in the browser until they sign in, and the DEC-003 banner encourages them to sign in. Accepted risk: an anonymous user who clears browser storage or switches browser before signing in loses legacy local-only content, including paid content.

## Acceptance Criteria

- [ ] After a signed-in owner opens a claimed profile on the original device, the local content that existed before is visible on another device signed in to the same account.
- [ ] Repeating the upload creates no duplicate entries.
- [ ] The server accepts uploads only for profiles whose ownerUid matches the authenticated caller's account, and rejects all other profiles.
- [ ] An upload call authenticated only by deviceId (no account authentication) is rejected and stores nothing.
- [ ] An upload for a profile that has no ownerUid yet (not claimed) is rejected and stores nothing.
- [ ] On sign-in, the client starts the upload only after claimProfiles has completed successfully.
- [ ] For an anonymous user, the client does not try to upload, and the local-only content stays in localStorage unchanged.
- [ ] An upload never changes star balances or unlock flags.
