## Finding

REQ-004 says local Oracle history is uploaded only after sign-in and claim of the profile. REQ-007 and DEC-002 say the upload happens whenever the 'owner' opens the profile, and an anonymous deviceId holder also counts as an owner under the current ownership rules. So it is unclear whether the upload endpoint accepts deviceId-authenticated callers for deep texts and compatibility readings. If it does, legacy paid content gets stored under a device-owned profile and stays device-bound, which goes against DEC-001's intent that paid content is tied to an account. If it does not, anonymous legacy users must sign in before their paid content is preserved. The two paths also need different endpoint authentication.

> When the owner opens a profile on a device whose localStorage holds deep texts, Oracle history or compatibility readings for that profile that are not yet on the server, the client must upload them once.

## Possible interpretations

- Upload of all content types only for signed-in callers, after claimProfiles (consistent with REQ-004)
- Upload for any owner, including anonymous deviceId owners; the content then moves to the account when the profile is claimed

## Resolution

Выгрузка всех типов контента работает только для вошедшего пользователя и только после claimProfiles, когда у профиля уже есть ownerUid. У анонимного пользователя локальный контент лежит в браузере до входа, а баннер из DEC-003 подталкивает его войти. — see DEC-004.
