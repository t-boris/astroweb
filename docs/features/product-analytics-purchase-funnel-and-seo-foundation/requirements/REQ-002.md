## Statement

The Stripe webhook sends purchase and subscription start/renewal/cancel events to GA4 via the Measurement Protocol for every successful event. The checkout session metadata carries the GA client_id and the analytics consent state at checkout time. For the astrologer subscription, subscribeAstrologer also writes the GA client_id, the Firebase Auth uid (if signed in) and the analytics consent state into subscription_data.metadata. The webhook reads these values from the Stripe subscription metadata for renewal and cancel events. The consent state recorded at subscription checkout applies to all events of that subscription. Later withdrawal of consent does not update the subscription metadata. When the relevant metadata (checkout session metadata for purchases and subscription start, subscription metadata for renewal and cancel) records analytics consent = granted, the event uses the stored real GA client_id, plus user_id (= Firebase Auth uid) if the user was signed in. When consent = granted is not in that metadata, the event is sent anonymously. It carries no user_id and no other user identifier. Its client_id is a pseudo client_id: a one-way hash (e.g. SHA-256, truncated and formatted as a GA-style client_id) derived deterministically from a Stripe identifier. For purchases this identifier is the Stripe session id. For renewal and cancel it is a Stripe identifier of that event. Open assumption, still to be confirmed: the invoice id for renewals, and the subscription id plus the cancel event id for cancels. Webhook retries for the same Stripe object produce the same client_id and the same transaction_id.

## Acceptance Criteria

- [ ] Checkout session metadata carries the GA client_id and the analytics consent status at checkout time.
- [ ] When creating the astrologer subscription checkout, subscribeAstrologer writes the GA client_id, the Firebase Auth uid (if signed in) and the analytics consent state into subscription_data.metadata, in addition to the checkout session metadata.
- [ ] With consent = granted in the checkout metadata, the purchase event includes the real GA client_id from the metadata, user_id (= Firebase Auth uid) if signed in, transaction_id = Stripe session id, value, currency and items.
- [ ] Without consent = granted in the checkout metadata, the purchase event is still sent, and its client_id is a one-way hash (e.g. SHA-256, truncated and formatted as a GA-style client_id) of the Stripe session id.
- [ ] Subscription start, renewal and cancel events are sent for every successful corresponding Stripe event.
- [ ] Renewal and cancel events read the client_id, uid and consent state from the Stripe subscription metadata, not from the current client state.
- [ ] Renewal and cancel events include the stored real client_id and user_id only when the subscription metadata has consent = granted.
- [ ] Renewal and cancel events whose subscription metadata lacks consent = granted are sent anonymously. Their pseudo client_id is a deterministic one-way hash of a Stripe identifier of that event. The exact identifier is still to be confirmed (proposed: the invoice id for renewal, the subscription id plus the cancel event id for cancel).
- [ ] Withdrawing analytics consent after subscription checkout does not change the subscription metadata. Renewal and cancel events of that subscription keep following the consent state recorded at subscription checkout.
- [ ] Without consent = granted, no user_id and no other identifier of the user is sent in any event.
- [ ] No pseudo client_id can be reversed to its source Stripe identifier. Each comes only from a one-way hash and never equals the raw Stripe identifier.
- [ ] Processing the same Stripe session or subscription event twice (webhook retry) produces an identical pseudo client_id and an identical transaction_id.
- [ ] Webhook retries do not produce duplicate purchases (same transaction_id).
- [ ] No birth data, names or emails appear in any event parameter.
- [ ] The /privacy page (REQ-004) and the GA4 legal reasoning checklist state that anonymous server-side events carry a pseudonymous identifier derived from the transaction id, which can be linked to the payment record in Stripe/Firestore.
- [ ] The /privacy page (REQ-004) states that analytics consent is recorded when the subscription starts and applies to later renewal and cancel events. It explains how to ask the operator (astroweb@mobilemindai.com) to stop attribution.
- [ ] The GA4 legal reasoning checklist covers keeping the consent state in Stripe subscription metadata and applying it to later renewal and cancel events.
