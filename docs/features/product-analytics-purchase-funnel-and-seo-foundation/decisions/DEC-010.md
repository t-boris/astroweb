## Context

The Firebase web app of astroweb-dev has no measurementId, so GA4 is not enabled. Server-side events need a Measurement Protocol API secret, and Acceptance Criteria #10 needs Search Console verification for natalmystic.com. These are actions in the owner's Google account. Answered by the owner on 2026-10-12.

## Alternatives

1. The owner creates the property, API secret and verification token and hands over the G-... id and token
2. Implement code only and mark the GA4 funnel exploration and Search Console acceptance items blocked

## Decision

Claude uses the owner's signed-in Google session in a MarkView browser tab to create the GA4 property and web data stream for natalmystic.com, link it to the Firebase project, create the Measurement Protocol API secret, configure the funnel exploration and verify Search Console. The API secret is stored only in Firebase Secret Manager (GA_API_SECRET) and is never printed, committed or written to a file in the repository. The measurement id (public) is committed in web/.env.production and functions/.env.astroweb-dev. Claude stops and asks if a step needs a password, 2FA code or billing action.

## Reason

The owner chose the fastest path that still keeps the secret out of the repository and chat.

## Consequences

Secret Manager must hold GA_API_SECRET before functions are deployed, because stripeWebhook binds it. The funnel exploration can only reference events GA4 has already received, so events must be generated on the live site first. Search Console verification uses the HTML meta tag emitted by the static shells (DEC-008).
