## Context

overview.md Acceptance Criteria #9 requires that the pages served by Hosting at /, /ru, /privacy and /ru/privacy each contain their own title, description, canonical, OG/Twitter tags and reciprocal hreflang. implementation/plan.md I-4 said to manage these on the client only. Hosting rewrites every path to one index.html, so client-only tags are invisible to OG scrapers and non-JS crawlers. DEC-003 accepted a client-only SPA with limited SEO, and the OUT list excludes an SSR/prerender migration. Answered by the owner on 2026-10-12 (question raised during implementation).

## Alternatives

1. Client-only head management in React on route change (plan I-4 as first written): amends Acceptance Criteria #9 to 'rendered by the client'; OG scrapers see one generic card for every URL
2. Cloud Function or Hosting rewrite that serves HTML with injected meta: more moving parts and a runtime cost per request

## Decision

A small inline Vite build plugin (no new library) emits one static HTML file per public route (/, /ru, /privacy, /ru/privacy) from index.html with route-specific title, meta description, canonical, hreflang (+x-default), OG/Twitter tags and, on the landing pages, JSON-LD. The app body is still rendered by the client, so this is not SSR/prerender of content. firebase.json enables cleanUrls so /ru and /ru/privacy resolve to the generated files, and sends an X-Robots-Tag: noindex header for /admin, /account and /profile/**. A client-side head sync keeps the tags correct during SPA navigation (language switch, private routes get meta robots noindex). Acceptance Criteria #9 stands as written.

## Reason

It is the only option that makes the served HTML itself carry per-URL tags without SSR, and it keeps the stack unchanged (Vite + Firebase Hosting). It reads Acceptance Criteria #9 literally.

## Consequences

implementation/plan.md I-4 is superseded by this decision. firebase.json hosting config changes (cleanUrls, headers). The build output gains extra HTML files that must be listed in sitemap.xml. Tag text must exist in both the plugin and the client head sync, so both read from one shared route metadata module. The raw HTML for /ru still contains the same JS bundle, so the UI language is set from the URL on load.
