**Предложение (это мой вывод, а не решение команды):** хранить всё в Firestore, где уже лежат профили. Новое хранилище не нужно. Доступ только через callable Functions, как сейчас (`tasks/personal-astrologer-spec.md:238`).

| Контент | Где хранить | Статус |
|---|---|---|
| История Оракула | `oracleHistory/{profileId}/items` | **Уже есть в коде** (`askOracle.ts:109-122`), сейчас пишется только для вошедших пользователей. Новая коллекция не нужна, нужен только эндпоинт для чтения. |
| Глубокие тексты интерпретации | `deepTexts/{profileId}/items/{sectionKey}_{lang}` | Новая коллекция в том же стиле. Один документ на секцию и язык, так что повторная загрузка просто перезапишет его. |
| Платные прочтения совместимости | `compatibilityReadings/{profileId}/items/{readingId}` | Новая коллекция, без лимита «последние 20», раз прочтения оплачены. |

**Почему так:**
- Структура повторяет уже существующий `oracleHistory`.
- Права доступа берутся из профиля: функция сначала проверяет владельца через `owner.ts`, потом читает или пишет данные. Это закрывает REQ-005.
- В документ профиля я бы тексты класть не стал. У Firestore есть лимит 1 MiB на документ (это внешний факт), а тексты могут быть длинными.
