## Context

DEC-013 left .github/workflows/firebase-deploy.yml untouched and out of scope. After the vitest pin (DEC-017) its only remaining failure is HTTP 400 'Secret environment variable overlaps non secret environment variable: STRIPE_SECRET_KEY' on six functions: the workflow writes STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET into functions/.env while the code binds them as Secret Manager secrets. GEMINI_API_KEY in that file is not referenced anywhere in functions/src. The owner asked on 2026-10-12 to fix CI now.

## Alternatives

1. Keep the .env step and remove the secrets: bindings from the code (changes how production reads Stripe keys)
2. Leave CI broken and deploy by hand only

## Decision

Remove the 'Create .env file for production' step from firebase-deploy.yml. Secrets stay in Secret Manager (bound in code); public values such as GA_MEASUREMENT_ID come from the committed functions/.env.astroweb-dev. This supersedes the 'firebase-deploy.yml is not changed here' part of DEC-013; the manual-deploy path stays available.

## Reason

The overlap is the last defect keeping pushes to main from deploying, and the .env lines duplicated secrets that Secret Manager already provides.

## Consequences

A push to main deploys again automatically. The repository secrets GEMINI_API_KEY, STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET are no longer read by the workflow (they can be removed from GitHub later). The fix can only be proven by the run that follows the merge.</consequences>
