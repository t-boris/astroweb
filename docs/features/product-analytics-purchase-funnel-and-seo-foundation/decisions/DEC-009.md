## Context

Scope item 6 and Acceptance Criteria #7 require 'stars spent per feature' in the Business tab. The code has no data source for it: functions/src/services/wallet.ts stores only a balance and spendFromWallet/spendInTx record nothing. DEC-006 and F-004 did not cover this. Answered by the owner on 2026-10-12.

## Alternatives

1. Drop 'stars spent per feature' from scope and amend the overview and Acceptance Criteria #7 (no schema change, KPI lost)

## Decision

Add a Firestore collection starSpends. Each star spend writes one row {walletKey, feature, stars, createdAt} in the same transaction as the wallet debit; each refund writes a negative row for the same feature. Spend sites: unlockFeature (interpretations, compatibility), askOracle (oracle), askRelationship (relationship), askInLetter (letter). adminStats aggregates net stars per feature for the selected period.

## Reason

A ledger is the only way to get a per-period, per-feature figure; it is written atomically with the debit so it cannot drift from the wallet, and refunds keep the figure net.

## Consequences

New collection; Firestore rules already deny all client access, so no rule change. Data is forward-only: spend before the deploy date is not reconstructable, so the Business tab shows 0 for earlier periods and says so. Wallet service signatures gain a feature argument. Tests cover debit+ledger atomicity inputs and the refund sign.
