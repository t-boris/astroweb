## Statement

Asking the Oracle is a paid action (it spends stars from the wallet), so it requires Google sign-in. The Oracle question/answer history shown for a profile must come from the server-side history (oracleHistory/{profileId}/items) of the signed-in account that owns the profile, so that it is identical on every device of that account. Anonymous (deviceId) users keep free usage but cannot ask the Oracle. Before asking, they are routed to Google sign-in, followed by claimProfiles. Oracle history that exists only in a browser's localStorage is uploaded to the server once, after the user signs in and the profile is claimed, and is then shown from the server.

## Acceptance Criteria

- [ ] A question asked on device A appears in the Oracle history on device B for the same signed-in account.
- [ ] The Oracle history shown in the UI is read from the server-side history (oracleHistory/{profileId}/items), not from localStorage.
- [ ] The askOracle endpoint rejects an unauthenticated (deviceId-only) caller with an authentication error, without spending stars and without storing any Q/A.
- [ ] An anonymous user who tries to ask the Oracle in the client is routed to Google sign-in; after sign-in, claimProfiles(deviceId) runs before the question can be asked.
- [ ] Every Oracle Q/A answered for a signed-in owner is stored server-side under that profile.
- [ ] If the answer fails and the stars are refunded, no Q/A entry is added to the server-side history.
- [ ] Oracle history that existed only in localStorage for a profile is uploaded to the server exactly once, after sign-in and claim of that profile. Afterwards it is shown from the server and is not duplicated on reload or on a repeated sign-in.
- [ ] A user who does not own the profile cannot read that profile's Oracle history.
- [ ] Anonymous users can still create profiles and use free features without signing in.
