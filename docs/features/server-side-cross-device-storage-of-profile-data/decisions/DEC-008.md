## Context

InterpretationView has a delete button for an Oracle history entry and RelationshipView one for a compatibility reading. REQ-002 and REQ-004 say nothing about deleting once the entries live on the server. Without a server delete, a deleted entry would come back on the next load. Answered by the owner on 2026-10-12.

## Alternatives

1. Hide the entry on this device only (it returns on another device and after clearing storage)
2. Remove the delete buttons

## Decision

A new owner-only callable deleteProfileContentItem removes one Oracle entry or one compatibility reading by id; the entry then disappears on every device. Uploading local content never deletes anything on the server. Entries that exist only in a browser (anonymous users) are removed from localStorage.

## Reason

The button keeps doing what it says and the stored history stays the single source of truth.

## Consequences

Deleting a paid reading is permanent; there is no undo. The read callable returns each entry's id so the client can delete it.
